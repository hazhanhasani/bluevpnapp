# بازیابی اتصال و پرداخت BlueVPN 3.0.76

این نسخه برای دو ایراد ریشه‌ای آماده شده است:

1. مخلوط‌شدن سرورهای رایگان، اشتراک قبلی و Premium فعلی در انتخاب خودکار.
2. شکست ساخت فاکتور BluePay در خطاهای موقت شبکه، Callback نامعتبر یا تغییر کلید رمزنگاری Railway.

## جداسازی واقعی Pool سرورها

غیرفعال‌کردن Subscription در v2rayNG به‌تنهایی پروفایل‌های قبلی را از فهرست سراسری MMKV حذف نمی‌کرد. در این نسخه تمام Subscriptionهای مدیریت‌شده BlueVPN که متعلق به Entitlement فعلی نیستند، با `removeServerViaSubid` به‌صورت فیزیکی پاک می‌شوند.

پیش از اتصال نیز سه محافظ اجرا می‌شود:

- سرور انتخاب‌شده باید عضو GUIDهای اشتراک فعال باشد.
- صف انتخاب خودکار فقط از Pool همان Entitlement ساخته می‌شود.
- Engine اجازه شروع روی پروفایل خارج از Pool فعال را نمی‌دهد.

در تغییر پلن رایگان به Premium یا جابه‌جایی اشتراک، انتخاب قبلی حذف و یک سرور معتبر از Pool جدید انتخاب می‌شود.

## ترکیب پاسارگارد، مرزبان و پنل سوم

کانفیگ‌های منابع Premium همچنان در یک خروجی اشتراکی ترکیب می‌شوند؛ اما ترتیب ترکیب Round-robin شده است. بنابراین اگر اولین پنل چند مسیر خراب داشته باشد، shortlist اتصال فقط با همان پنل پر نمی‌شود و مسیر سالم پنل‌های دیگر نیز فرصت تست دارد.

این تغییر منابع Premium را از هم حذف نمی‌کند؛ فقط سرور رایگان را از Premium جدا می‌کند و تنوع Provider را در انتخاب اولیه حفظ می‌کند.

## بازیابی BluePay

- فقط قرارداد رسمی `POST /api/v1/invoices` با `X-API-Key` و `Idempotency-Key` استفاده می‌شود.
- در Timeout یا خطاهای 502/503/504 فقط یک Retry امن با همان بدنه و همان Idempotency-Key انجام می‌شود.
- Callback فقط وقتی ارسال می‌شود که HTTPS عمومی و معتبر باشد؛ آدرس localhost یا تنظیم قدیمی حذف می‌شود تا Callback پیش‌فرض فروشگاه BluePay استفاده شود.
- Origin درخواست Railway برای ساخت Callback معتبر در اولویت قرار گرفته است.
- پاسخ `success: false` حتی با HTTP 2xx خطا محسوب می‌شود.
- پیام واقعی BluePay و `X-Request-ID` در خطا نگه داشته می‌شود.

## مهاجرت کلید رمزنگاری

اگر API Key قبلاً با `SESSION_SECRET` رمز شده و بعداً `DATA_ENCRYPTION_KEY` تعریف شده باشد، نسخه‌های قبلی ممکن بود دیگر قادر به خواندن کلید BluePay نباشند. نسخه 3.0.76 برای Decrypt به‌ترتیب این کلیدها را امتحان می‌کند:

1. `DATA_ENCRYPTION_KEY`
2. `SESSION_SECRET`
3. کلیدهای جداشده با ویرگول در `DATA_ENCRYPTION_KEY_PREVIOUS`
4. کلید سازگاری قدیمی

رمزگذاری‌های جدید همیشه با کلید اول انجام می‌شوند.

## تنظیم Railway

در صورت تغییر کلید قبلی، مقدار قبلی را موقتاً نگه دارید:

```env
DATA_ENCRYPTION_KEY=کلید_فعلی
DATA_ENCRYPTION_KEY_PREVIOUS=کلید_قبلی
```

پس از Deploy، یک‌بار API Key فروشگاه BluePay را در پنل باز و ذخیره کنید تا با کلید فعلی دوباره رمزگذاری شود. سپس در صورت اطمینان از مهاجرت، کلید قبلی قابل حذف است.
