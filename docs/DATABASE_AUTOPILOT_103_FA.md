# BlueVPN Database Autopilot 1.0.3

## علت حذف اطلاعات

نسخه قبلی اگر PostgreSQL در دسترس نبود، بدون توقف روی فایل زیر می‌رفت:

`/app/data/bluevpn.db`

فایل‌های داخل کانتینر Railway دائمی نیستند و با Deploy جدید حذف می‌شوند.
به همین علت پنل دوباره با دیتابیس خالی بالا می‌آمد.

## رفتار جدید

- در محیط Railway فقط PostgreSQL پذیرفته می‌شود.
- اگر PostgreSQL تنظیم یا قابل دسترس نباشد، Deploy شکست می‌خورد.
- پنل خالی و ظاهراً سالم دیگر جایگزین Backend خراب نمی‌شود.
- اتصال با این حالت‌ها خودکار تشخیص داده می‌شود:
  - DATABASE_URL
  - DATABASE_PRIVATE_URL
  - POSTGRES_URL
  - POSTGRES_PRIVATE_URL
  - PGHOST / PGUSER / PGPASSWORD / PGDATABASE
- اتصال تا ۴۵ بار با فاصله دو ثانیه امتحان می‌شود.
- در صورت امکان، دیتابیس PostgreSQL گمشده نیز خودکار ساخته می‌شود.
- تمام جداول با `create_all` ساخته می‌شوند.
- ستون‌های جدید با Migration خودکار اضافه می‌شوند.
- نام ستون‌های قدیمی به ساختار جدید منتقل می‌شوند.
- اگر SQLite قدیمی هنوز موجود باشد، داده‌های آن یک‌بار به PostgreSQL وارد می‌شوند.
- نسخه ساختار و گزارش Migration داخل جدول `bluevpn_schema_meta` ذخیره می‌شود.
- وضعیت، تعداد رکوردها و گزارش Migration در پنل مدیریت نمایش داده می‌شوند.

## نکته بازیابی

اگر فایل SQLite قبلی یا دیتابیس PostgreSQL قبلی واقعاً حذف شده باشد، کد
نمی‌تواند داده‌ای را که دیگر وجود ندارد بازسازی کند. اما اگر فایل قدیمی هنوز
در مسیر `LEGACY_SQLITE_PATH` یا `/app/data/bluevpn.db` وجود داشته باشد،
انتقال آن خودکار انجام می‌شود.

## نصب بدون تغییر دستی Dockerfile

فایل `railway.json` سرویس را از `/app/server/run_combined.py` اجرا می‌کند. این فایل توسط ZIP و ربات Deploy قابل بروزرسانی است؛ بنابراین محافظت ربات از Dockerfile مانع نصب این اصلاح نمی‌شود.
