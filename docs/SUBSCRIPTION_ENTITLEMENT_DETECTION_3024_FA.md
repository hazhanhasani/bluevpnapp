# تشخیص قطعی اشتراک فعال — BlueVPN 3.0.24

## مشکل

پس از فعال‌سازی یا تمدید، Backend اشتراک معتبر داشت اما اپلیکیشن ممکن بود مقدار
`active=false` قدیمی را تا پنج دقیقه از SharedPreferences بخواند و در صفحه اصلی
«نیاز به تمدید» نمایش دهد. نصب نسخه جدید نیز زمان آخرین Sync نسخه قبلی را حفظ می‌کرد.

## اصلاح

- آخرین سفارش `activated` همراه با مدت پلن به‌عنوان منبع پایدار Entitlement بررسی می‌شود.
- API فیلدهای `entitlement_active`، `active_reason` و `remaining_seconds` را برمی‌گرداند.
- وضعیت‌های صریح `disabled`، `blocked` و `expired` بر Entitlement مقدم هستند.
- Android اعتبار را از Boolean سرور، وضعیت، تاریخ انقضا، حجم و Entitlement محاسبه می‌کند.
- کش حساب با تغییر Version Code بی‌اعتبار می‌شود.
- حساب محلی غیرفعال هیچ‌وقت از کش پنج‌دقیقه‌ای استفاده نمی‌کند.
- بازگشت از صفحه حساب/پرداخت و اولین بازشدن صفحه اشتراک Sync اجباری انجام می‌دهد.

## نتیجه

اشتراک فعال بلافاصله در صفحه اصلی نمایش داده می‌شود و کاربر برای اصلاح وضعیت نیازی
به خروج از حساب، پاک‌کردن داده برنامه یا صبرکردن پنج دقیقه ندارد.
