BlueVPN 2.2.2 — رفع ارسال‌نشدن پیام GuardCore

این ZIP را مستقیم برای ربات Deploy ارسال کن.

علت مشکل:
در نسخه 2.2.1 درخواست دستی GuardCore فقط زمانی ساخته می‌شد که
GuardCore مستقیماً داخل همان پلن انتخاب شده بود. اگر پلن فقط
PasarGuard یا Marzban داشت، فعال‌سازی کامل می‌شد اما پیام ربات ساخته نمی‌شد.

اصلاحات:
- اولین GuardCore دستی فعال به‌عنوان گزینه اختیاری پیش‌فرض استفاده می‌شود.
- بعد از خرید کاربر، پیام بله/خیر GuardCore ارسال می‌شود.
- بعد از فعال‌سازی دستی مدیر نیز همان پیام ارسال می‌شود.
- لازم نیست GuardCore را داخل تک‌تک پلن‌ها انتخاب کنی.
- اگر پلن یک GuardCore خودکار مشخص داشته باشد، همان ساختار خودکار حفظ می‌شود.
- سفارش‌های فعال‌شده ۷۲ ساعت اخیر که پیامشان جا افتاده بازیابی می‌شوند.
- پیام‌های ارسال‌نشده هر ۶۰ ثانیه دوباره امتحان می‌شوند.
- خطای دقیق ارسال تلگرام داخل صف GuardCore ذخیره می‌شود.
- PasarGuard و Marzban همچنان کاملاً خودکار هستند.
- GuardCore فقط بعد از تأیید ادمین و ارسال لینک Subscription اضافه می‌شود.

بعد از Deploy:
1. مطمئن شو حداقل یک GuardCore با حالت «دستی از طریق ربات» فعال است.
2. BOT_TOKEN و ADMIN_IDS در Railway موجود باشند.
3. ربات هنگام شروع، سفارش فعلی جاافتاده را بازیابی می‌کند.
4. اگر پیام فوری نیامد، داخل ربات دکمه «صف GuardCore» را بزن.
5. در پنل وب نیز بخش «صف GuardCore» و دکمه «ارسال دوباره به ربات» موجود است.
