# بازگردانی Workflow پایدار GitHub در BlueVPN 3.0.27

## علت تغییر

نسخه 3.0.26 برای مقابله با خطای تخصیص Runner، فایل Build را پیچیده کرده بود: Runner از ورودی Workflow انتخاب می‌شد و ربات در صورت شکست یک اجرای دوم با `workflow_dispatch` ایجاد می‌کرد. برای حذف این لایه و بازگشت به مسیر قبلاً موفق، Workflow دقیقاً به ساختار نسخه 3.0.25 بازگردانده شد.

## وضعیت نهایی

- Runner ثابت: `ubuntu-latest`
- محرک Build: Push روی شاخه `main` یا اجرای دستی ساده
- بدون ورودی Runner
- بدون اجرای دوم روی `ubuntu-24.04`
- بدون Retry خودکار Workflow از ربات Deploy
- صف Build حفظ می‌شود، اما مسیر Runner ثابت و ساده است
- هر Upload تأییدشده فقط یک Push و یک Build ایجاد می‌کند

این اصلاح تغییری در کد OTP، فراز اس‌ام‌اس، دیتابیس یا منطق برنامه Android ایجاد نمی‌کند.
