# BlueVPN 3.0.16 — مدیریت پرداخت‌های معلق BluePay

## مشکل

در نسخه‌های قبلی، سفارش‌های `pending`، `waiting`، `processing` و `unpaid` می‌توانستند بدون زمان انقضای محلی در دیتابیس باقی بمانند. همچنین هر بار لمس دکمه پرداخت ممکن بود فاکتور جدیدی ایجاد کند.

## اصلاحات

- ستون `orders.expires_at` با مهاجرت خودکار اضافه شد.
- سفارش‌های قدیمی با توجه به `ttl_minutes` زمان‌دار می‌شوند.
- سفارش منقضی حذف نمی‌شود و به `expired_local` می‌رود.
- فاکتور معتبر قبلی برای همان کاربر و پلن بازگردانده می‌شود.
- فاکتورهای تکراری قدیمی‌تر به `superseded` تغییر می‌کنند.
- ساخت فاکتور برای هر کاربر با قفل دیتابیس سریالی می‌شود.
- پاک‌سازی در شروع سرویس و سپس هر 300 ثانیه اجرا می‌شود.
- Webhook یا استعلام `paid` می‌تواند سفارش `expired_local` یا `superseded` را بازیابی کند.
- پنل مدیریت تعداد فاکتورهای فعال، گذشته از مهلت، منقضی و جایگزین‌شده را نشان می‌دهد.

## متغیرهای محیطی

```env
BLUEPAY_PENDING_CLEANUP_ENABLED=true
BLUEPAY_CLEANUP_INTERVAL_SECONDS=300
BLUEPAY_CREATING_GRACE_SECONDS=120
```

## وضعیت‌های جدید

- `expired_local`: مهلت محلی تمام شده، ولی پرداخت دیرهنگام هنوز قابل بازیابی است.
- `superseded`: فاکتور معتبر جدیدتری جایگزین این سفارش شده، ولی پرداخت دیرهنگام آن همچنان پردازش می‌شود.

## نکته مالی

هیچ سفارش قدیمی حذف نمی‌شود. این رفتار برای حفظ سابقه حسابداری و امکان بازیابی پرداخت‌های دیرهنگام ضروری است.
