# بازیابی قفل ربات Deploy در BlueVPN 3.0.29

مشکل قبلی این بود که هنگام منتظرماندن GitHub Actions برای Hosted Runner، شناسه چت داخل `ACTIVE_CHAT_JOBS` باقی می‌ماند و ربات همه ZIPهای بعدی را رد می‌کرد.

## اصلاحات

- هر عملیات یک Token یکتا، زمان شروع، زمان آخرین فعالیت، Task و Run ID دارد.
- پاک‌سازی عملیات فقط وقتی انجام می‌شود که Token همان عملیات باشد؛ Task قدیمی نمی‌تواند قفل عملیات جدید را حذف کند.
- دکمه `🔓 آزادسازی عملیات` و دستور `/unlock` عملیات منتظر را لغو می‌کنند.
- هنگام آزادسازی، Run مرتبط در GitHub نیز در صورت امکان Cancel می‌شود.
- اگر Build بیش از ۱۵ دقیقه در صف Runner بماند، ربات خطا را اعلام و قفل را خودکار آزاد می‌کند.
- اگر اجرای GitHub تا ۵ دقیقه پس از Commit ساخته نشود، عملیات پایان می‌یابد و قفل آزاد می‌شود.
- Watchdog هر دقیقه قفل‌های محلی قدیمی را بررسی می‌کند.
- ارسال ZIP جدید، عملیاتی را که فقط منتظر Runner است به‌صورت امن جایگزین می‌کند.

## متغیرها

همه تنظیمات دارای مقدار پیش‌فرض‌اند و ثبت متغیر جدید اجباری نیست:

```env
RUN_DISCOVERY_TIMEOUT_SECONDS=300
RUNNER_QUEUE_TIMEOUT_SECONDS=900
JOB_STALE_TIMEOUT_SECONDS=1800
JOB_CRITICAL_GRACE_SECONDS=900
```

## نصب روی رباتی که همین حالا قفل است

چون نسخه قدیمی دکمه آزادسازی ندارد، یک بار سرویس BlueVPN در Railway باید Restart شود تا قفل حافظه پاک شود. سپس Hotfix 3.0.29 از طریق همان ربات ارسال می‌شود. از آن به بعد Restart دستی برای این مشکل لازم نیست.
