# بازسازی چرخه پرداخت BluePay در BlueVPN 3.0.78

## مشکل اصلی

پاک‌سازی قبلی، رکورد واقعی سفارش را از جدول `orders` حذف می‌کرد. در محیط PostgreSQL، پیامک‌های فاکتور به `orders.id` وابسته‌اند؛ بنابراین حذف سفارش می‌توانست با Foreign Key شکست بخورد و صفحه مدیریت فقط `Internal Server Error` نمایش دهد. حذف سفارش همچنین باعث می‌شد Callback دیرهنگام BluePay دیگر سفارش متناظر را پیدا نکند.

## معماری جدید

- پیش‌نویس محلی که هرگز شناسه یا لینک درگاه نگرفته است قابل حذف است.
- هر سفارشی که `payment_id` یا `payment_url` دارد، سابقه مالی محسوب و Archive می‌شود.
- سفارش Archiveشده از چرخه خرید و استفاده مجدد خارج می‌شود اما برای Callback، Audit، پیامک و بازیابی پرداخت باقی می‌ماند.
- پاک‌سازی دستی هر فاکتور را جداگانه استعلام می‌کند؛ پرداخت دیرهنگام را بازیابی، فاکتور Pending را در BluePay لغو و خطای هر ردیف را مستقل ثبت می‌کند.
- خطای یک فاکتور باعث شکست کل عملیات پاک‌سازی نمی‌شود.

## تنظیمات امن

- مقدار ماسک‌شده API Key یا Callback Secret هرگز به‌عنوان کلید واقعی ذخیره نمی‌شود.
- برای فعال‌شدن درگاه، API Key و Callback Secret هر دو لازم‌اند.
- اگر کلید رمزگذاری تغییر کرده باشد، پنل پیام مشخص برای ثبت دوباره Secretها نمایش می‌دهد.

## تست Sandbox

دکمه «تست امن اتصال BluePay در Sandbox» یک فاکتور آزمایشی ۱۰۰۰ تومانی در محیط مستقل Sandbox می‌سازد و آن را Best-effort منقضی می‌کند. این تست پول واقعی، کارت یا فاکتور Live را درگیر نمی‌کند.
